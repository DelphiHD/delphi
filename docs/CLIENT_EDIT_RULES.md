# Client edit pass: what changes and what is protected

**Status: draft for Kaycee. Nothing here is wired in yet.**

Two artefacts from one generation:

- `<Name> - <Tier> - v<N>.md` — the analyst record. Unchanged, full technical,
  every citation and every piece of jargon. Kaycee's copy.
- `<Name> - <Tier> - v<N> (Client).md` — the same report, edited for readability.
  Same sections, same headers, same gate bullets, same structure. Easier to read.
- `<Name> - <Tier> - v<N>.docx` — the deliverable, rendered from the client
  version. Keeps the name it has today.

The chart page's click-through text reads the client version, so the gate
bullets stay: the editor simplifies how they read, never removes them.

## Protected terms

These are load-bearing. The editor may explain them; it may not replace them
with an everyday synonym, and it may not delete them.

- Center names: Head, Ajna, Throat, G, Heart, Sacral, Spleen, Solar Plexus, Root
- Defined, Undefined, Open
- Type names: Generator, Manifesting Generator, Projector, Manifestor, Reflector

- Hanging gate
- Incarnation Cross, Right Angle, Left Angle, Juxtaposition

## Exaltation and detriment

The words "exaltation", "exalted", "detriment" and "in detriment" are allowed:

- on a heading line
- immediately after a placement token, e.g. `P Sun 17.1 Exalted`,
  `P South Node 42.4 Detriment`

and nowhere else. The fixing state stays recorded where a reader can look it up;
the prose explains what it does without the vocabulary.

**Open question for Kaycee.** The house rule "mechanics not pathology, detriments
are named with full directness" still stands, and the prose now has to convey a
detriment's effect without using the word. Whether "runs against the grain here"
is right, or something else is, is a voice decision rather than a code one.
